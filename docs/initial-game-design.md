# 《방과 후, 종이 울리면》 초기 게임 기획안

> **2026-09-16 구현 방향 변경:** 현재 프로토타입은 8방향 이동과 4방향 캐릭터 표현을 사용하는 2D 탑다운 학교생활 게임으로 전환했습니다. 아래 내용은 전환 전의 초기 기획 기록이며, 현재 구현과 실행 방법은 [기본 시스템 가이드](basic-systems.md)를 참고하세요.

> 문서 버전: 0.1
>
> 장르: 2D 스토리 액션 플랫폼 / 학교 생활 어드벤처
>
> 엔진 제안: Godot 4.x
>
> 목표 플랫폼: PC(키보드·게임패드), 이후 콘솔 검토

## 1. 한 줄 소개

전학 첫날부터 시간이 반복되는 학교에서, 플레이어가 교내를 빠르게 누비고 친구들과 관계를 쌓으며 사라진 학생의 흔적을 찾는 2D 스토리 플랫폼 게임.

## 2. 기획 의도와 방향

### 핵심 경험

1. **손맛 좋은 이동**: 복도, 계단, 옥상과 체육관을 달리고 뛰며 학교 공간 자체를 놀이터처럼 느낀다.
2. **관계가 만드는 변화**: 대화 선택과 작은 부탁의 결과가 인물 관계, 이동 경로, 결말에 반영된다.
3. **익숙한 장소의 낯선 얼굴**: 평범한 학교가 방과 후에는 비밀 통로와 위험한 공간으로 변한다.
4. **짧고 강한 연출**: 플레이를 오래 끊지 않는 대화와 인게임 연출로 감정선을 전달한다.

### 참고작 활용 원칙

《산나비》에서는 빠르고 유연한 횡스크롤 이동, 플레이와 서사가 자연스럽게 이어지는 연출, 명확한 실루엣과 타격감의 **설계 원리**를 참고한다. 캐릭터, 세계관, 서사, 시각 요소, 고유 이동 장치는 새롭게 설계하며 원작의 표현을 복제하지 않는다.

### 디자인 원칙

- **이동 중 재미가 우선**: 목적지까지 가는 시간도 플레이가 되게 한다.
- **대화는 짧고 선택은 선명하게**: 한 대화의 기본 길이는 30~90초로 잡는다.
- **선택에는 예고와 결과가 있다**: 중요한 분기 전에 충분한 정보를 준다.
- **실패 비용은 낮게**: 위험 구간 직전에 자동 체크포인트를 둔다.
- **학교 생활과 미스터리를 함께 진행**: 일상 활동이 단순 미니게임이 아니라 단서와 관계의 획득 방식이 된다.

## 3. 세계관과 이야기

### 배경

가까운 미래의 공립학교 **해솔고등학교**. 오래된 본관과 자동화된 신관이 연결되어 있다. 매일 오후 6시 종이 울리면 일부 학생이 사라지고 학교는 아침으로 되돌아가지만, 주인공과 몇몇 학생만 이전 하루를 어렴풋이 기억한다.

### 주인공

- 임시 이름: **한별**
- 전학 첫날 시간 반복에 갇힌 2학년 학생
- 학생증에 발생한 오류로 교내 시설의 잠긴 장치를 잠시 활성화할 수 있다.
- 적극적, 신중함, 유머의 세 대화 태도를 플레이어가 선택한다.

### 주요 인물

| 인물 | 역할 | 겉으로 보이는 목표 | 숨겨진 갈등 | 플레이 보상 |
|---|---|---|---|---|
| 서윤 | 반장 | 모두를 무사히 귀가시키기 | 반복을 알고도 침묵함 | 교무실·방송실 출입 |
| 민재 | 방송부 | 폐쇄된 방송실 복구 | 실종 학생의 마지막 녹음을 소지 | 지도에 음향 단서 표시 |
| 다온 | 육상부 | 대회 출전 기록 달성 | 반복 때문에 기록이 인정되지 않음 | 이동 기술 훈련 |
| 보건 선생님 | 조력자 | 학생 상태 관찰 | 학교의 과거 실험과 연관 | 회복·기억 보존 기능 |
| ‘빈자리’ | 미스터리 인물 | 존재를 기억해 달라고 요청 | 시간 반복의 중심 | 진실 및 결말 분기 |

### 전체 서사 구조

- **프롤로그 — 전학 첫날**: 기본 이동과 상호작용 학습, 오후 6시에 첫 반복 발생.
- **1장 — 남겨진 방송**: 동아리 활동을 통해 실종 학생의 음성 기록을 수집.
- **2장 — 잠긴 신관**: 친구들의 부탁을 해결해 출입 권한과 새로운 이동 기술 확보.
- **3장 — 기억하는 사람들**: 각 인물의 비밀과 반복을 유지하는 이유가 드러남.
- **4장 — 마지막 종례**: 관계도와 수집한 단서에 따라 반복의 유지·종료·변형을 선택.

예상 결말은 기본 3종으로 기획하되, 단순한 마지막 선택이 아니라 주요 인물 퀘스트와 단서 수집 결과를 조건으로 사용한다.

## 4. 핵심 게임 루프

1. **아침 조회**: 오늘의 주요 일정, 인물 위치, 소문을 확인한다.
2. **수업·쉬는 시간**: 제한된 시간 안에 이동해 대화, 탐색, 짧은 활동을 수행한다.
3. **방과 후**: 위험 구간을 플랫폼 액션으로 돌파하고 핵심 단서를 찾는다.
4. **오후 6시**: 사건이나 보스급 추격전이 발생하고 하루가 종료된다.
5. **다음 반복**: 일부 단서, 관계 기억, 해금한 이동 기술을 유지해 새로운 경로를 연다.

한 번의 하루는 초기에는 15~20분, 후반에는 지름길과 기술 숙련으로 8~12분에 돌 수 있게 설계한다. 중요한 대화 중에는 시간이 흐르지 않으며, 시간 제한 임무는 명확히 표시한다.

## 5. 조작과 이동

### 기본 조작안

| 행동 | 키보드 | 게임패드 | 비고 |
|---|---|---|---|
| 이동 | A/D | 왼쪽 스틱 | 가속·감속 적용 |
| 점프 | Space | A/Cross | 짧게 누르기와 길게 누르기 높이 차등 |
| 대시 | Shift | RT/R2 | 지상·공중 각 1회, 착지 시 회복 |
| 상호작용 | E | X/Square | 대상 강조 및 아이콘 표시 |
| 학생증 링크 | Q | LB/L1 | 지정 장치로 빠르게 당겨 이동 |
| 대화 넘기기 | Space/Enter | A/Cross | 설정에서 자동 재생 지원 |
| 일시정지 | Esc | Menu | 일지·지도·설정 |

### 이동 감각의 초기 목표값

아래 값은 프로토타입 시작점이며 플레이테스트로 조정한다.

- 달리기 최고 속도: 초당 260px
- 지상 가속 시간: 0.12초 / 감속 시간: 0.10초
- 점프 정점 도달 시간: 약 0.32초
- 코요테 타임: 0.10초
- 점프 입력 버퍼: 0.12초
- 대시 시간: 0.16초 / 대시 재사용 대기: 0.25초
- 낙하 최고 속도 제한 및 정점 부근 중력 완화 적용

### 확장 이동 기술

- **학생증 링크**: 천장 센서, 표지판, 지정 고리에 링크해 빠르게 당겨진다. 전투용 갈고리가 아닌 학교 설비 해킹이라는 고유 설정을 부여한다.
- **벽차기**: 체육관 훈련 퀘스트 완료 후 획득한다.
- **슬라이드**: 낮은 장애물을 통과하며 달리기 흐름을 유지한다.
- **친구 도움**: 관계 조건을 만족하면 특정 구간에 발판, 문 개방, 원격 방송 등의 지원이 나타난다.

## 6. 상호작용 시스템

### 대상 유형

- **인물**: 대화, 선물, 동행 요청
- **환경**: 사물함, 게시판, 책상, 자판기, 방송 장비
- **이동 장치**: 문, 엘리베이터, 학생증 링크 지점
- **수집물**: 음성 기록, 쪽지, 학생증 스티커

### 동작 규칙

1. 캐릭터 주변의 상호작용 범위에서 가장 가까우며 바라보는 방향에 있는 대상을 우선한다.
2. 대상에는 동일한 위치의 아이콘과 짧은 행동 문구(예: `E 조사하기`)를 표시한다.
3. 여러 대상이 겹치면 방향키로 대상을 전환할 수 있다.
4. 중요한 상호작용은 상태 변화 전 확인을 제공하고, 일반 조사는 즉시 실행한다.
5. 상호작용 중 위험을 받지 않도록 대화 공간을 안전 구역으로 만들거나 대화를 취소한다.

### 상태 조건 예시

`1장 진행 중` + `민재 관계 2 이상` + `방송실 열쇠 소지`일 때만 숨겨진 녹음 재생 선택지가 나타난다. 잠긴 선택지는 조건을 공개할지 여부를 퀘스트 성격에 따라 설정한다.

## 7. 대화 다이얼로그

### 화면 구성

- 하단 대화창, 화자 이름, 인물 반신 초상 또는 인게임 표정
- 한 화면 기준 한글 2~3줄, 줄당 약 28자 권장
- 선택지는 기본 2~3개이며 태도 아이콘과 예상 성격을 함께 표시
- 자동 재생, 대화 기록, 즉시 표시, 글자 속도 조절, 음성 볼륨 제공
- 이미 읽은 일반 대화만 길게 눌러 빠르게 넘길 수 있으며 새 대사와 선택지는 자동 정지

### 대화 데이터 예시

```json
{
  "id": "ch01_broadcast_entrance",
  "speaker": "minjae",
  "text": "이 시간에 방송실에 온 사람은 네가 처음이야.",
  "portrait": "uneasy",
  "choices": [
    {
      "text": "마지막 방송에 대해 물어본다.",
      "next": "ask_last_broadcast",
      "conditions": ["clue:last_broadcast_note"],
      "effects": ["relationship:minjae:+1"]
    },
    {
      "text": "장비 수리를 돕겠다고 한다.",
      "next": "offer_help",
      "effects": ["quest:repair_console:start"]
    }
  ]
}
```

### 분기 관리 원칙

- 서사 진행 상태는 `chapter`, `quest`, `flag`로 분리한다.
- 호감도 숫자만으로 인물을 판단하지 않고, 신뢰·약속 이행 같은 의미 있는 플래그를 함께 쓴다.
- 되돌릴 수 없는 선택에는 별도 시각·음향 신호를 제공한다.
- 대화 데이터와 번역 텍스트를 코드에서 분리해 검수와 현지화를 쉽게 한다.

## 8. 학교 공간 구성

학교는 하나의 큰 연결형 맵처럼 느껴지되 제작과 로딩은 구역 단위로 나눈다.

| 구역 | 일상 기능 | 방과 후 변화 | 대표 이동 과제 |
|---|---|---|---|
| 본관 교실·복도 | 수업, 친구 대화 | 사물함과 문 배치 변화 | 달리기·슬라이드 |
| 중앙 계단 | 층간 이동 | 일부 계단 붕괴 | 벽차기 연속 구간 |
| 체육관 | 이동 튜토리얼 | 자동 장비가 장애물로 작동 | 대시·링크 조합 |
| 도서관 | 단서 조사 | 서가가 미로를 형성 | 관찰·경로 기억 |
| 방송실 | 주요 서사 | 음향에 반응하는 장치 활성화 | 타이밍 퍼즐 |
| 신관·옥상 | 후반 핵심 구역 | 비정상 공간으로 확장 | 전체 기술 종합 |

지도는 방문한 방과 확인한 연결로만 공개한다. 퀘스트 목적지는 정확한 핀 대신 기본적으로 구역을 표시하고, 접근성 설정에서 정밀 안내를 선택할 수 있다.

## 9. 위험 요소와 액션

학생을 직접 공격하는 구조보다 **회피, 추격, 환경 해제**를 중심으로 한다.

- 순찰하는 교내 관리 드론
- 닫히는 방화문, 무너지는 발판, 전기 누전 구간
- 소리를 감지하는 비정상 방송 장치
- 기억이 왜곡된 학생의 그림자(정화 또는 회피 대상)

피격 시 ‘집중력’이 감소하며 0이 되면 최근 체크포인트로 돌아간다. 적을 쓰러뜨리는 대신 학생증 링크로 장치를 과부하시키거나 친구의 도움으로 경로를 바꾼다. 보스는 대화 선택, 이동 시험, 환경 퍼즐이 결합된 추격전으로 구성한다.

## 10. 성장, 퀘스트, 수집

### 성장 방식

- 메인 진행: 새로운 구역 및 학생증 기능 해금
- 인물 퀘스트: 친구 도움 능력과 결말 조건 해금
- 이동 도전: 기술 자체보다 배지, 외형, 기록 단축 요소 제공
- 수집: 세계관 기록과 대화 선택지 확장

### 퀘스트 유형

- **부탁**: 분실물 찾기, 장비 수리처럼 관계를 보여 주는 짧은 임무
- **약속**: 특정 시간·장소를 지켜야 하며 다른 일정과 선택 충돌
- **조사**: 여러 단서를 조합해 결론을 선택
- **도전**: 제한 시간 이동, 추격, 장애물 구간

일지에는 현재 목표, 관련 인물, 시간 조건, 최근 대화를 기록한다. 실패한 약속도 서사 상태로 인정해 곧바로 게임 오버시키지 않는다.

## 11. UI·시청각 방향

### 아트

- 2D 픽셀 아트 또는 저해상도 일러스트 기반, 캐릭터 실루엣을 명확히 구분
- 낮에는 따뜻한 자연광과 생활감, 방과 후에는 청록·자홍의 비정상 조명 대비
- 상호작용 가능 요소에는 과도한 외곽선 대신 일정한 색의 작은 반사광 사용
- 빠른 이동 중 배경 패럴랙스와 잔상은 가독성을 해치지 않는 범위로 제한

### 사운드

- 종소리, 의자 끄는 소리, 복도 방송 등 학교의 일상음을 주요 모티프로 사용
- 시간 반복이 가까워질수록 배경음의 박자와 방송 잡음이 미세하게 변함
- 점프, 착지, 대시, 링크 성공음은 서로 다른 음역으로 즉시 구분
- 핵심 대사는 부분 보이스를 우선 검토하고 전체 더빙은 제작 규모 확정 후 판단

### 접근성

- 키보드와 게임패드 전체 키 재지정
- 흔들림, 섬광, 잔상 강도 조절 및 끄기
- 색상에만 의존하지 않는 위험·상호작용 표시
- 자막 크기·배경 투명도·글자 속도 조절, 화자별 이름 표시
- 대시 토글, 버튼 연타 대체, 추격 난이도 완화
- 주요 플랫폼 구간 건너뛰기 또는 피해 무시 옵션을 별도 보조 모드로 제공

## 12. 기술 구조 제안(Godot 4.x)

### 주요 씬

```text
Main
├── WorldManager
│   ├── CurrentZone
│   └── TransitionLayer
├── Player
├── NPCManager
├── QuestManager
├── DialogueManager
├── TimeLoopManager
└── UI
    ├── HUD
    ├── InteractionPrompt
    ├── DialogueUI
    ├── JournalUI
    └── PauseMenu
```

### 핵심 컴포넌트

- `PlayerController`: 상태 머신 기반 이동, 입력 버퍼, 애니메이션 요청
- `InteractionDetector`: 범위·방향·우선순위로 상호작용 대상 선택
- `Interactable`: 프롬프트, 조건, 실행 신호를 제공하는 공통 인터페이스
- `DialogueManager`: 대사 로드, 조건 평가, 효과 실행, 기록 저장
- `QuestManager`: 퀘스트 단계와 목표 이벤트 구독
- `TimeLoopManager`: 시간 진행, 일정, 반복 종료, 영구·일시 상태 분리
- `SaveManager`: 버전이 포함된 세이브 슬롯, 설정 파일과 진행 파일 분리
- `EventBus`: 시스템 간 직접 참조를 줄이는 제한된 전역 신호 모음

### 상태 저장 구분

- **영구 상태**: 발견한 핵심 단서, 관계 기억, 기술 해금, 설정
- **루프 상태**: 오늘 획득한 물건, 인물 위치, 열린 문, 일정 결과
- **세션 상태**: 현재 체력, 체크포인트, 일시적 연출 상태

자동 저장은 하루 시작, 중요 선택 직후, 구역 전환 시 수행한다. 쓰기 도중 종료돼도 복구할 수 있도록 임시 파일에 저장한 뒤 교체한다.

## 13. MVP 범위

### 버티컬 슬라이스(플레이 20~30분)

- 본관 복도, 교실, 체육관, 방송실의 4개 구역
- 기본 이동, 점프, 대시, 학생증 링크
- NPC 3명, 짧은 관계 퀘스트 2개
- 조건·선택·효과를 지원하는 대화 시스템
- 하루의 오전/쉬는 시간/방과 후/반복 1회
- 체크포인트, 자동 저장, 설정과 핵심 접근성 옵션
- 1개의 추격 시퀀스와 1개의 서사적 선택

### MVP에서 제외

- 전체 챕터, 모든 결말, 전체 보이스
- 온라인 협동·경쟁, 사용자 제작 콘텐츠
- 절차 생성 맵, 복잡한 전투·장비·경제 시스템
- 모바일 버전과 터치 조작

## 14. 제작 일정 예시(소규모 팀, 16주)

| 단계 | 기간 | 결과물 | 종료 조건 |
|---|---:|---|---|
| 프리프로덕션 | 1~2주 | 이동 테스트, 서사 개요, 아트 기준 | 핵심 루프와 MVP 범위 합의 |
| 이동 프로토타입 | 3~5주 | 회색 박스 체육관 | 목표 조작 지표와 카메라 검증 |
| 시스템 제작 | 6~9주 | 상호작용, 대화, 퀘스트, 저장 | 데이터 기반 시나리오 1개 완주 |
| 콘텐츠 제작 | 10~13주 | 4개 구역, NPC, 추격전 | 처음부터 끝까지 플레이 가능 |
| 폴리시 | 14~15주 | 아트·사운드·접근성·최적화 | 치명적 버그 0건, 목표 프레임 유지 |
| 테스트·배포 | 16주 | 데모 빌드, 피드백 보고서 | 외부 테스트와 회귀 테스트 완료 |

### 최소 역할 구성

- 게임 디자이너/시나리오 1명
- Godot 프로그래머 1명
- 2D 아티스트/애니메이터 1명
- 사운드는 외주 또는 파트타임을 고려

## 15. 검증 지표와 테스트 질문

### 정량 지표

- 튜토리얼 구간 완료율 90% 이상
- 첫 10분 내 이동 조작 이해율 80% 이상
- 대화 선택 후 결과를 이해했다는 응답 80% 이상
- 플랫폼 구간 재시도 중앙값 3회 이하
- 데모 종료까지 치명적 진행 막힘 0건

### 관찰 질문

- 목적지를 몰라도 이동 자체가 즐거운가?
- 낮과 방과 후의 동일 공간이 충분히 다르게 느껴지는가?
- 어떤 선택이 관계를 바꿨는지 플레이어가 설명할 수 있는가?
- 반복이 단순 재플레이가 아니라 새 정보를 이용하는 과정으로 느껴지는가?
- 대화가 액션 흐름을 지나치게 자주 끊지는 않는가?

## 16. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 빠른 이동과 좁은 실내 맵 충돌 | 카메라 멀미, 잦은 벽 충돌 | 긴 복도와 수직 샤프트 중심의 방 설계, 예측 카메라 테스트 |
| 시간표가 플레이어를 압박 | 탐색·대화 기피 | 중요 대화 중 시간 정지, 완화 모드, 다음 루프의 지름길 제공 |
| 분기 폭증 | 제작·QA 비용 증가 | 큰 줄기는 합류시키고 상태 반응을 풍부하게 설계 |
| 일상과 미스터리의 분위기 단절 | 서사 몰입 저하 | 일상 소품과 대화가 모두 핵심 단서로 이어지게 구성 |
| 참고작과 지나친 유사성 | 작품 정체성 약화 | 학생증 링크, 시간표, 관계 기반 도움을 독자 핵심으로 검증 |

## 17. 첫 프로토타입 완료 조건

- 키보드와 게임패드로 이동·점프·대시·링크를 모두 수행할 수 있다.
- 코요테 타임과 입력 버퍼가 자동 테스트 또는 디버그 표시로 확인된다.
- 하나의 NPC에게 접근해 조건부 선택지가 있는 대화를 끝낼 수 있다.
- 대화 결과로 문이 열리고 퀘스트 단계가 변경된다.
- 추락하면 2초 안에 최근 체크포인트에서 재개한다.
- 하루가 종료되면 루프 상태만 초기화되고 영구 단서는 유지된다.
- 게임을 종료하고 다시 실행해도 저장된 진행과 설정이 복원된다.
