# 관계·게임 시간·신체 상태

## 현재 동작

- 관계는 고정 캐릭터 ID 사이의 **방향 그래프**로 관리합니다. A→B와 B→A는 독립적입니다.
- 서윤·민재의 첫 대화를 끝까지 마치면 해당 NPC→플레이어 호감도가 5 증가합니다. 취소하면 지급하지 않고, 첫 보상은 재생해도 중복 지급하지 않습니다.
- 호감도가 5 이상이면 다음 상호작용부터 친근한 재방문 대사를 사용합니다.
- 게임은 1일차 08:00에 시작합니다. 기본 속도는 **실제 1초 = 게임 1분**입니다.
- 대화·일시정지 중에는 게임 시간과 허기·갈증·피로가 멈춥니다.
- 운동장 간식대·급수대·벤치, 교실 휴식 침상에서 E로 섭취·휴식·수면을 실행합니다.
- HUD는 시간, 허기·갈증·피로, 가장 최근 호감도 변화를 표시합니다.

현재 보급 장소는 횟수 제한 없는 시스템 확인용입니다. 가방·아이템 수량·비용·품절 처리는 아직 없습니다. 수치가 100이 되어도 피해·이동 페널티를 자동으로 부여하지 않습니다. 스태미나는 [별도 단기 행동 자원](combat-system.md)으로 구현했으며 피로와 합치지 않습니다. 캐릭터의 휴식·수면 완료 시 스태미나를 전량 회복합니다.

## 책임 분리

| 클래스 | 책임 |
|---|---|
| `RelationshipState` | 한 방향의 호감도 값과 범위 |
| `RelationshipGraph` | 방향별 간선 보관, 기본값 조회, 스냅샷 검증 |
| `RelationshipService` | 증감·상한/하한 적용·변경 알림 |
| `AffinityDialogueEffect` | 데이터 기반 대화 완료 보상, 일회성 지급 |
| `RelationshipDialogueInteraction` | 호감도 조건에 맞는 대화 ID 선택 |
| `GameClock` | 누적 게임 분, 실제 시간 배율, 시간 이동과 잠금 |
| `NeedsProfile` | 초기 수치와 시간당 변화율 설정 Resource |
| `NeedsState` | 개별 캐릭터의 수치와 마지막 반영 시각 |
| `NeedsService` | 등록된 캐릭터의 시간 진행·섭취·휴식·수면 계산 |
| `NeedsComponent` | 캐릭터와 서비스 연결, 행동 허용 검사, 변경 시그널 |
| `ConsumableDefinition` | 음식·음료의 허기·갈증 감소량 |
| `ConsumeInteraction`, `RestInteraction` | 장소별 상호작용을 신체 상태 기능에 연결 |

순수 데이터/규칙 클래스는 `RefCounted` 또는 `Resource`입니다. 입력·UI·씬에 접근하지 않습니다. `SessionState`가 관계 서비스, 시계, 캐릭터 저장소, 신체 상태 서비스를 소유하며 `InGame`이 실제 시간 진행을 구동합니다. HUD에는 문자열과 숫자만 전달합니다.

## 관계 그래프

```text
seoyun ── 호감도 5 ──→ player
seoyun ←─ 호감도 0 ─── player
```

- 범위: **-100 ~ 100**, 없는 간선의 기본값: **0**.
- 단순 조회는 간선을 생성하지 않습니다. 0으로 돌아간 간선은 제거합니다.
- 빈 ID, 자기 자신과의 관계, 무한대/NaN은 거부합니다.
- 맵에 노드가 없어도 ID로 기록할 수 있습니다. 아직 등록되지 않은 유효한 ID도 허용하므로 콘텐츠에서 ID 철자를 일관되게 관리하세요.
- 한쪽 변경이 반대쪽에 전파되지 않습니다. 양쪽 변화가 필요한 사건은 방향별 효과를 각각 작성합니다.
- 변경이 실제로 발생했을 때만 `affinity_changed(from_id, to_id, previous, current)`를 보냅니다.
- 가족·연인 같은 두 사람의 공통 관계 유형은 현재 호감도 간선에 포함하지 않습니다.

```gdscript
session.relationships.add_affinity(&"seoyun", &"player", 5.0)
var value := session.relationships.get_affinity(&"seoyun", &"player")
```

### 대화 완료 효과

기존 대화 JSON의 `on_complete`에 다음 효과를 추가합니다. 기존 `schema_version: 1`을 그대로 사용하며, 새 효과 처리기는 `GameCoordinator`에서 등록합니다.

```json
{
  "type": "add_affinity",
  "parameters": {
    "from": "seoyun",
    "to": "player",
    "amount": 5,
    "once_key": "seoyun_first_greeting_reward"
  }
}
```

`from`, `to`, `amount`는 필수입니다. `once_key`는 선택 항목으로, 생략하면 매번 완료할 때 적용합니다. 지정하면 세션 플래그에 완료 사실을 보관합니다. 서로 다른 보상은 고유한 키를 사용하세요. 한 번에 양쪽 관계를 바꾸는 두 효과에도 서로 다른 지급 키가 필요합니다.

효과 묶음은 전체 검증을 통과해야 실행됩니다. 대화 취소에는 완료 효과가 없습니다. 저장할 때 관계 그래프와 플래그를 함께 보관하므로 불러온 뒤에도 첫 보상을 다시 받지 않습니다.

### 관계 조건으로 대화 선택

NPC의 `Interaction.action`에 `RelationshipDialogueInteraction`을 설정합니다.

| 속성 | 의미 |
|---|---|
| `dialogue_id` | 조건 미달일 때의 기본 대화 |
| `from_id`, `to_id` | 조회할 관계의 정확한 방향 |
| `minimum_affinity` | 조건을 만족하는 최소 호감도 |
| `matched_dialogue_id` | 조건 충족 시 사용할 대화 |

선택은 상호작용 실행 시 최신 관계로 판단합니다. 이미 시작한 대화는 기존 다이얼로그 세션의 복사본으로 끝까지 진행합니다. 대화 도중 선택지 UI나 복잡한 조건 트리는 후속 범위입니다.

## 게임 시간

`GameClock.total_minutes()`는 첫날 00:00부터 누적한 게임 분입니다. 실수로 보관하므로 짧은 프레임의 시간도 누적하고, 화면은 분 단위로 표시합니다.

- `advance_real_seconds(delta)`: 배율을 적용한 실제 프레임 진행.
- `advance_minutes(minutes)`: 수업·휴식 같은 명시적 시간 이동.
- `acquire_pause()` / `release_pause(token)`: 각 시스템이 자신의 시간 잠금만 해제.
- 음수 시간, 유한하지 않은 값, 시간 진행 알림 도중의 재진입은 거부.
- 배율을 0으로 설정하면 자동 진행을 멈추고 명시적 시간 이동만 사용할 수 있음.

대화 컨트롤러와 일시정지 연결부가 각자 토큰을 소유합니다. 대화 완료·취소, 메뉴 재개, 씬 종료 시 자기 토큰을 정리하며 다른 시스템의 잠금은 유지합니다. 시간 잠금은 저장하지 않습니다.

## 신체 상태와 콘텐츠 수치

허기·갈증·피로는 **0이 가장 낮고 100이 가장 높은 상태**입니다. 기본 학생 설정은 `data/life/student_needs.tres`에서 편집합니다.

| 항목 | 초기값 | 게임 1시간당 변화 |
|---|---:|---:|
| 허기 | 20 | +4 |
| 갈증 | 15 | +6 |
| 피로 | 10 | 활동 중 +3 |
| 휴식 중 피로 | — | -12 |
| 수면 중 피로 | — | -20 |

휴식/수면의 피로 회복률은 같은 시간의 활동 피로 증가를 대체합니다. 허기·갈증은 휴식 중에도 같은 속도로 증가합니다. 모든 값은 0~100으로 제한합니다.

| 장소 | 위치 | 행동 |
|---|---|---|
| 간식대 | 운동장 `(900, 760)` | 허기 30 감소 |
| 급수대 | 운동장 `(1000, 760)` | 갈증 35 감소 |
| 벤치 | 운동장 `(1080, 620)` | 게임 30분 경과, 피로 6 회복 |
| 휴식 침상 | 교실 `(1120, 240)` | 게임 60분 경과, 피로 20 회복 |

해당 물체 아래쪽으로 접근해 위를 바라보고 E를 누르세요. 간식·물은 지금은 시간이 즉시 흐르지 않는 섭취 행동입니다. `snack.tres`, `water.tres`에서 회복량을 편집하고, `RestInteraction`의 `minutes`, `sleeping`으로 휴식 종류와 시간을 지정합니다.

`CharacterDefinition.needs_profile`이 없는 캐릭터는 신체 상태 시뮬레이션에 등록하지 않습니다. 현재 플레이어·서윤·민재에는 공통 학생 설정을 연결했습니다. 프로필은 공유하는 설정이므로 실행 중 변경하지 않습니다.

### 맵 밖 NPC와 일관성

게임 중 한 번 등록된 캐릭터는 노드가 사라져도 서비스가 상태를 계속 갱신합니다. 저장 후 재실행해서 아직 프로필을 연결하지 않은 NPC는 `last_updated_minutes`로 누락 시간을 보관하고, 다시 등록할 때 차이만 한 번 반영합니다. 처음 생성되는 캐릭터는 생성 시각에 초기 수치로 시작합니다.

시간 이동은 모든 등록 캐릭터를 갱신한 다음 변경 알림을 보냅니다. 변경 알림 처리 중 재귀적인 시간 이동·섭취·휴식은 거부합니다. 긴 시간 이동과 여러 번의 짧은 이동은 동일한 결과를 냅니다.

휴식/수면은 현재 즉시 완료되는 시간 이동입니다. `NeedsComponent`가 임시 행동 잠금을 보관하고, 서비스는 해당 시간의 회복률을 적용합니다. 임시 잠금이나 휴식 동작을 영구 활동 상태로 기록하지 않아, 시간 이동 알림 중 저장해도 불러온 캐릭터가 영구히 잠들어 있지 않습니다.

## 저장 기반

`SessionState.snapshot()` / `restore()`로 다음을 함께 저장·복원합니다.

- 진행 플래그와 일회성 보상 지급 기록
- 캐릭터 상태 및 허기·갈증·피로·마지막 반영 시각
- 방향별 관계 그래프
- 게임 시간과 실제 시간 배율

JSON 변환 가능한 데이터만 사용합니다. 복원은 **월드에 연결하기 전의 새 세션**에 수행합니다. 모든 영역을 임시 객체에서 검증하고 한 번에 적용하므로, 관계나 신체 상태 데이터에 오류가 있어도 나머지만 부분 적용하지 않습니다. 현재 시계보다 미래인 신체 상태 기록도 거부합니다.

세션·관계·시계 형식은 버전 1, 캐릭터 저장소는 버전 3입니다. 기존 캐릭터 버전 1·2를 읽을 수 있으며, 없던 신체 상태는 등록 시 기본 프로필로 초기화합니다. 노드 참조, 행동 잠금, AI 이동 명령은 저장하지 않습니다.

**파일 저장 슬롯·자동 저장, 현재 맵과 좌표 복원은 아직 별도 구현이 필요합니다.** 이 스냅샷만으로 플레이 위치까지 복원되지는 않습니다.
