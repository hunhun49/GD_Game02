# 다수전: 공격 판정 영역과 프레임 단위 판정

근접 공격은 **타격 구간에 공격 Hitbox와 적의 Hurtbox가 겹치는지 검사**합니다. 공격 시작 시 정한 대상은 조준 보조·제압에만 사용하며, 일반 공격의 피해 대상을 고정하지 않습니다. 실제로 겹친 여러 적에게 각각 타격 요청을 만듭니다.

## 3명 훈련 실행

Godot에서 [multi_combat_demo.tscn](../gd-game-02/scenes/combat/multi_combat_demo.tscn)을 열고 **F6**으로 현재 씬을 실행합니다. 기본 F5 학교 씬의 훈련 로봇은 기존 위치에 있습니다.

- 커서를 세 로봇의 중앙에 놓고 좌클릭하면 하나의 공격으로 셋 모두를 타격할 수 있습니다.
- 처음에는 로봇들이 가드합니다. 피해 대신 각자의 체간이 쌓이고 훈련이 시작됩니다.
- 로봇은 일반 → 푸름 → 붉음 → 보라 패턴을 사용하며, 첫 응답 간격은 0.7 / 0.9 / 1.1초입니다.
- 우클릭 가드·튕김, Shift 돌진, Q 보라색 공격은 기존 조작입니다.
- 공격·가드 동작을 마친 뒤 로봇 근처에서 E를 누르면 **로봇 3명과 양쪽의 전투 동작·체간을 초기화**합니다. 플레이어 체력은 살아 있는 동안 회복하지 않습니다.
- R은 훈련 종료와 체크포인트 복귀입니다. 전투 불능일 때는 플레이어 체력을 회복합니다.
- 한 적만 멀어져 훈련을 중단해도 다른 적과의 전투가 이어지면 플레이어의 가드·체간은 유지합니다.

## 역할과 씬 배치

```text
InGame                         현재 플레이어·활성 구역의 판정 범위
├─ CombatResolver              이 범위의 타격 요청만 처리
├─ Player
│  ├─ 몸 CollisionShape2D      이동을 막는 충돌
│  ├─ Hurtbox                  피격 영역: CircleShape2D
│  ├─ AttackHitbox             재사용하는 공격 영역
│  └─ Combat
│     ├─ Attack                타격 시간·방향·대상별 적중 기록
│     └─ Skills                스킬 슬롯·쿨다운
└─ CurrentZone
   └─ TrainingDummy × 3        각자 고유 ID와 Combat·Hitbox·Hurtbox
```

공격 Hitbox는 캐릭터 또는 무기 소켓의 **Node2D 공간 계층** 아래에 둡니다. AttackComponent는 `hitbox_path`로 해당 영역을 참조합니다. 현재 기본 경로는 `../../AttackHitbox`입니다.

| 구성 | 책임 |
|---|---|
| `AttackHitbox` | 공격 모양과 Hurtbox의 실제 겹침 검사, 벽 검사, 접촉 대상 수집 |
| `Hurtbox` | 피격 모양, 소유 Combat 참조, 활성 여부 |
| `AttackComponent` | 준비·타격·회수, 공격 실행 번호, 이미 맞힌 캐릭터 ID 집합 |
| `CombatResolver` | 프레임의 후보 수집, 방어 결과 확정, 상쇄 우선 처리, 일괄 적용 |
| 피격 측 `CombatComponent` | 요청 검증·방어 상태 제공, 체력·체간 컴포넌트에 결과 적용 |
| `HitResolver` / `DamageResolver` | 기존 대응 규칙과 피해·저항 계산 유지 |

## 판정 영역의 구현

기본 Hitbox는 공격 데이터의 사거리·각도를 여러 볼록 부채꼴로 나누어 재사용합니다. 크기가 같은 공격마다 새 노드를 생성하지 않습니다. 최대 360도 범위를 지원하며, 준비·회수 구간에서는 공격 판정이 비활성입니다.

겹침은 양쪽 Shape2D와 현재 월드 변환을 사용합니다. 따라서 적의 중심점이 사거리 밖이어도 Hurtbox의 가장자리가 닿으면 맞습니다. Godot의 [`Shape2D.collide`](https://docs.godotengine.org/en/stable/classes/class_shape2d.html#class-shape2d-method-collide)를 사용하며, Area의 이전 프레임 겹침 목록에 의존하지 않습니다.

Hurtbox는 이동 충돌과 분리된 Area2D입니다. `enabled = false`, 비활성 CollisionShape2D, 숨겨진/제거 중인 영역은 감지하지 않습니다. 자신·아군·다른 InGame 범위·무적·제어 잠금·전투 불능 대상은 전투 자격 검사에서 제외합니다.

겹침 뒤에는 공격자에서 Hurtbox까지 벽을 검사합니다. 전투 캐릭터의 몸은 이동을 막지만, 앞의 적 한 명이 뒤의 적을 향한 휘두르기까지 차단하지 않도록 벽 검사에서 제외합니다.

### 무기 모양으로 바꾸기

1. AttackHitbox를 무기 소켓 아래로 배치하고 AttackComponent의 `hitbox_path`를 수정합니다.
2. `use_attack_sector = false`로 설정합니다.
3. Hitbox 아래에 검·창·주먹 모양의 `CollisionShape2D`를 추가합니다. 여러 개도 가능합니다.
4. 무기 애니메이션이 방향을 직접 제어한다면 `orient_to_attack = false`로 설정합니다. 그러면 소켓/Hitbox의 실제 월드 변환을 사용합니다. 기본값 true는 공격 시작 방향을 사용합니다.
5. 피해 처리는 콜라이더 접촉 콜백에 추가하지 않습니다. 기존 타격 시간과 공통 판정 흐름을 유지합니다.

여러 Hurtbox를 가진 캐릭터는 각 Hurtbox의 `combat_path`가 같은 Combat을 가리키게 합니다. 기본 경로는 `../Combat`입니다. 피해는 Hurtbox 수와 관계없이 캐릭터 ID 기준 한 번만 발생합니다. 캐릭터 ID는 같은 InGame 범위에서 고유해야 합니다.

## 한 공격의 적중 기록

```text
공격 실행 #123
├─ 적 A: 적중 처리 완료 → 계속 겹치거나 재진입해도 추가 피해 없음
├─ 적 B: 적중 처리 완료
└─ 적 C: 타격 구간 도중 새로 진입 → 한 번 판정
```

- 빈 공간에서 시작한 공격도 준비/타격 중 들어온 적에게 적중할 수 있습니다.
- 하나의 타격 구간에서는 적별로 한 번만 판정합니다. 가드·튕김·회피도 해당 접촉을 소비합니다.
- 다음 공격 실행에서 적중 기록을 새로 만듭니다.
- 낮은 프레임 속도로 준비·타격 구간을 한 번에 통과해도 타격 구간을 건너뛰지 않고 한 번 수집합니다.
- 제압은 기존처럼 선택한 붕괴 대상 하나에게 적용합니다.

## 같은 프레임의 판정 규칙

```mermaid
flowchart LR
    A[모든 캐릭터의 동작 갱신] --> B[활성 Hitbox 후보 수집]
    B --> C[대상별 방어·피해 결과 계산]
    C --> D[상쇄·돌진 패링으로 취소할 공격 확정]
    D --> E[적중 기록과 양쪽 동작 먼저 확정]
    E --> F[체력·체간 적용 및 시그널]
```

1. 일반·푸름·붉음·보라 모두 같은 판정기로 보냅니다. 같은 프레임의 가드·회피·상쇄 상태를 먼저 읽고, 그 뒤 피해를 적용합니다.
2. **체간 붕괴:** 같은 프레임에 가드로 확정된 공격은 모두 가드됩니다. 그 결과 붕괴해도 이미 확정한 다른 가드 판정을 피격으로 바꾸지 않습니다. 이후 프레임부터 방어가 해제됩니다.
3. **동시 치명타:** 같은 프레임에 확정된 유효 공격은 공격자가 다른 타격으로 쓰러져도 적용합니다. 서로 동시에 쓰러지는 결과가 가능합니다.
4. **보라색 상쇄:** 같은 프레임에 서로의 Hurtbox에 닿을 수 있는 보라색 공격은 모두 상쇄 대상입니다. 하나의 Q 공격이 여러 적의 보라색 공격과 상쇄할 수 있습니다. 상쇄된 공격 실행 전체를 취소하므로 다른 적에게 남은 피해가 발생하지 않습니다. 회수 시간은 캐릭터마다 한 번만 설정합니다.
5. **상쇄는 무적이 아님:** 같은 프레임에 들어온 별개의 일반 공격은 여전히 맞을 수 있습니다.
6. **돌진 패링:** 동일 프레임에 방향·시간·이동 조건을 만족한 붉은 공격들은 모두 패링할 수 있습니다. 결과를 확정한 뒤 돌진을 종료합니다. 다음 프레임의 새 공격까지 자동으로 막지는 않습니다.
7. **일관된 적용 순서:** 결과 적용 순서는 공격자 ID·대상 ID로 정렬합니다. 피해 계산과 카운터 확정은 이 순서 이전에 수행합니다.

기존 `receive_attack()`은 제압과 명시적 즉시 제출을 위한 호환 경로로 남아 있으며, 같은 판정기를 통과합니다. 일반 근접 공격은 직접 이를 호출하지 않고 Hitbox 수집 경로를 사용해야 프레임 단위 판정에 참여합니다.

## 수명·초기화·잠금

- 요청은 실행 번호와 WeakRef를 사용합니다. 취소·초기화·새 공격·공격자 삭제 뒤 오래된 요청은 피해를 주지 않습니다.
- 적용 전에 공격별/대상별 접촉을 소비하고 참가 캐릭터의 재진입을 막습니다.
- 일시정지는 미처리 요청을 보관하고, 재개 시 유효성을 다시 확인합니다.
- 대화 잠금·구역 이탈·삭제 중인 대상은 판정에서 제외합니다. 한 대상이 제외돼도 다른 유효한 대상은 처리합니다.
- 구역 교체·R 복귀·훈련 초기화는 판정기 대기열을 비웁니다. 시그널 처리 도중 초기화가 발생하면 나머지 이전 결과 적용을 중단합니다.
- InGame마다 판정기가 분리됩니다. 체력·체간의 원본은 계속 캐릭터 컴포넌트가 소유합니다.

## 검증과 남은 범위

`multi_combat_test.gd`는 다중 적중·중복 Hurtbox·재진입·새 대상 진입·진영·저항·피격 영역 크기·무기 모양·벽·초기화·일시정지·공격자 삭제·실제 마우스 입력·적별 전투 이탈을 검사합니다. 동시 치명타와 다중 상쇄는 공격 갱신 순서를 뒤집어서도 확인합니다.

```sh
godot --headless --path gd-game-02 --script res://tests/multi_combat_test.gd
godot --path gd-game-02 res://scenes/combat/multi_combat_demo.tscn
```

현재는 물리 프레임의 현재 모양을 비교하는 근접 판정입니다. 프레임 사이를 완전히 통과하는 고속 무기·투사체의 연속 충돌, 별도의 다단 히트 차수, 적의 추격·포위 AI, 반사·연쇄 피해는 후속 범위입니다. Hurtbox 수집은 현재 범위의 등록된 영역을 순회하므로 대규모 탄막용 공간 분할 최적화는 아직 하지 않았습니다. 자동 검사와 별도로 실제 다수전 난이도·손맛 튜닝이 필요합니다.

검증 결과: Godot 4.7.2에서 **11개 검사 모음, 630개 항목 통과, 실패 0건**. 실제 렌더링으로 3명 가드 적중, 보라색 예고·동시 상쇄, HUD와 밀집된 적의 기호 표시를 확인했습니다.
