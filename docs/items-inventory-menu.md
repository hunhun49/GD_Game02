# 아이템·인벤토리·캐릭터 메뉴

## 실행과 조작

Godot에서 기본 게임을 **F5**로 실행한 뒤 **I** 또는 오른쪽 위 **캐릭터 · 가방** 버튼으로 엽니다. 창 위쪽의 **캐릭터 상태 / 인벤토리 / 스킬** 탭으로 이동합니다. **I**, **Esc**, 닫기 버튼으로 게임에 돌아갑니다. 기존 Tab 대상 변경과 전투 조작은 유지됩니다.

메뉴를 열면 게임과 학교 시간이 일시정지합니다. 아이템 사용·장착 변경은 메뉴 안에서 즉시 적용됩니다. 대화 중이거나 다른 시스템이 게임을 일시정지한 경우 메뉴가 그 일시정지를 가져오지 않습니다. 창을 닫는 Esc가 즉시 일시정지 메뉴를 다시 열지 않도록 입력을 소비합니다.

### 캐릭터 상태

이름·현재 구역·게임 시간, 체력·스태미나·체간·허기·갈증·피로, 상태 효과와 남은 시간을 표시합니다. 아직 캐릭터 초상화 리소스는 없으므로 학생 기록 카드를 표시합니다.

### 인벤토리

24칸이며 아이템별 최대 수량으로 묶습니다. 전체·음식·치료·중요 필터, 아이콘·보유 수량, 선택한 아이템의 설명과 사용 가능 여부를 표시합니다. 기존 묶음부터 채우고 남은 수량을 빈칸에 넣습니다. 공간이 없으면 획득 API가 **받지 못한 수량**을 반환하므로 호출자가 월드에 남기거나 보상을 보류할 수 있습니다.

| 아이템 | 초기 수량 | 효과 | 최대 묶음 |
|---|---:|---|---:|
| 삼각김밥 | 3 | 허기 25 감소 | 10 |
| 생수 | 3 | 갈증 30 감소 | 10 |
| 구급 상자 | 2 | 체력 30 회복 | 5 |
| 해독제 | 2 | `poison` 태그 상태 제거 | 10 |
| 붕대 | 2 | `bleed` 태그 상태 제거 | 10 |
| 화상 연고 | 2 | `burn` 태그 상태 제거 | 10 |
| 학생증 | 1 | 중요한 물건으로 보관 | 1 |

초기 소지품은 세션당 한 번 지급합니다. 구역 이동·메뉴 재개·저장 복원 시 다시 지급하지 않습니다. 수량이 0인 빈 가방을 복원해도 재지급하지 않습니다. 초기 수량은 `SessionState.STARTING_ITEMS`에 있습니다.

체력이 가득 찼거나 치료할 상태가 없으면 아이템을 소모하지 않습니다. 전투 불능·상호작용 잠금 상태도 사용을 거절합니다. 체력 회복은 부활이 아닙니다. 화상 연고는 더움을, 붕대는 일반 체력 손실을 치료하지 않습니다. 학생증의 출입 조건 연동은 아직 없으며 직접 사용하지 않는 소지품입니다.

### 스킬

현재 배운 스킬의 설명·피해·재사용 시간·남은 시간을 표시하며 Q 슬롯에 장착·해제할 수 있습니다. 현재 기본 스킬은 상쇄격입니다. 새로 배운 스킬은 같은 목록에 나타납니다. 쿨다운은 스킬 ID별로 유지되므로 장착을 바꿔 초기화할 수 없습니다. 장착 변경은 다음 스킬 사용부터 적용됩니다.

## 책임 분리

```text
ItemDefinition (Resource)
  ID·이름·설명·분류·최대 묶음·아이콘·사용 효과
      └─ ItemUseEffect
          ├─ RestoreNeedsItemEffect → 음식·음료
          ├─ HealItemEffect → 체력 회복
          └─ CleanseItemEffect → 태그별 치료

ItemCatalog → 검증된 설정 리소스 보관·복제 조회
ItemStack → 슬롯 번호·아이템 ID·수량
InventoryState → 획득·소모·용량·스냅샷·변경 이벤트
ItemUseContext → 대상 캐릭터·신체 상태 서비스·일시정지 사용 허가

GameCoordinator → 메뉴 열기·닫기와 일시정지 소유권
CharacterMenuPresenter → 게임 상태 ↔ 화면 값·사용/장착 요청
CharacterMenu → 상단 탭·공통 창
  ├─ CharacterStatusTab
  ├─ InventoryTab
  └─ SkillsTab
```

인벤토리에 게임 오브젝트나 공유 리소스의 보유 수량을 저장하지 않습니다. 조회 결과와 설정은 복제본입니다. UI의 각 탭은 표시용 Dictionary를 받아 그리며 플레이어·인벤토리·전투 노드를 직접 찾지 않습니다. Presenter가 사용 요청을 다시 검증하고 해당 시스템을 호출합니다.

현재 아이템은 **한 개의 사용 효과 리소스**를 가집니다. 새 작동 방식은 `ItemUseEffect`의 `is_valid()`, `unavailable_reason(context)`, `apply(context)`를 구현합니다. 사용 가능성 조회는 상태를 변경하지 않아야 하며, `apply()`는 실제 효과가 적용된 경우에만 `true`를 반환해야 합니다. 여러 효과를 한 아이템에 합치는 경우 부분 성공과 소모 정책을 구현한 별도 복합 효과가 필요합니다.

### 사용의 안전성

사용 시 1개를 먼저 예약하고 효과를 실행합니다. 실행 중 재진입한 사용·추가·삭제·복원은 거절합니다. 실패하면 원래 슬롯에 수량을 돌려주고, 성공하면 예약된 1개만 소모한 상태로 변경 이벤트를 보냅니다. 효과 콜백에서도 이미 예약된 수량을 보므로 중복 사용이나 무료 회복을 방지합니다.

메뉴는 게임 전체를 일시정지하므로 일반 전투 회복 API를 그대로 호출하면 회복되지 않습니다. 메뉴 사용 Context가 명시적으로 허용한 경우에만 `HealthComponent.heal(amount, allow_paused)` 경로를 사용합니다. 기존 피해·상태 시간·회복 호출의 일시정지 규칙은 기본 인자로 유지됩니다. 음식은 세션의 NeedsService, 치료는 StatusEffects를 통해 적용합니다.

## 아이템 추가·획득

1. `data/items/`에 `ItemDefinition` 리소스를 만듭니다.
2. 고유 `item_id`, 최대 묶음과 표시 정보, 필요한 `use_effect`를 지정합니다.
3. `ItemCatalog.PATHS`에 리소스 이름을 등록합니다. 저장 파일의 ID를 해석하려면 복원 시에도 같은 카탈로그가 있어야 합니다.
4. 획득 지점·보상에서 세션의 인벤토리 API를 호출합니다.

```gdscript
var remainder := session.inventory.add(&"water", 3)
# remainder > 0이면 그 수량의 지급을 보류하거나 월드에 남깁니다.

var entries := session.inventory.entries()
var count := session.inventory.count(&"student_card")
```

`entry(slot)` / `entries()`는 값 복사본이고 슬롯 번호는 다른 아이템을 사용해도 바뀌지 않습니다. 빈 슬롯은 이후 획득 시 재사용합니다. 메뉴가 오래된 선택을 보유했더라도 사용 시 실제 슬롯·수량·효과 조건을 다시 확인합니다.

현재 월드 드롭·줍기·상점·장비·드래그 이동·정렬·분할 UI는 추가하지 않았습니다. 음식대와 급수대의 기존 즉시 섭취 동작도 그대로 유지됩니다. 플레이어 가방은 세션 소유이며 NPC별 가방과 개별 장비 내구도는 후속 범위입니다.

## 저장 데이터

`SessionState.snapshot()`은 버전 **2**이며 인벤토리와 초기 지급 여부를 포함합니다. 복원은 각 도메인의 임시 객체를 모두 검증한 뒤 한 번에 반영합니다. 슬롯 중복, 잘못된 수량·타입·범위, 모르는 아이템 ID는 전체 복원을 거절합니다. 소지품을 조용히 삭제하거나 넘치는 수량을 잘라내지 않습니다.

이전 버전 1 세션은 인벤토리 없이 복원하고 첫 월드 구성 시 초기 소지품을 한 번 지급합니다. JSON의 숫자가 실수로 파싱되는 경우도 정수 값과 범위를 검증해 처리합니다.

이번 구현은 기존 JSON 스냅샷에 인벤토리를 연결한 것입니다. 디스크 저장 슬롯 UI와 파일 기록은 아직 없습니다. 스킬의 보유·장착·쿨다운 및 상태 효과의 실행 상태는 아직 영구 저장하지 않습니다.

## 검증

```bash
godot --headless --path gd-game-02 --script res://tests/inventory_test.gd
```

묶음·용량·빈 슬롯 재사용, 외부 변경 차단, JSON 저장·복원·버전 이전, 초기 지급 중복 방지, 음식·치료·회복, 실패 시 반환, 콜백 재진입, 일시정지 허가, 실제 키보드·마우스로 세 탭 이동·아이템 사용·스킬 장착을 검사합니다.

검증 결과: Godot 4.7.2에서 **14개 검사 모음, 827개 항목 통과, 실패 0건**. 인벤토리·메뉴 전용 61개 검사를 포함합니다. 상태·인벤토리·스킬 탭은 실제 렌더링으로 확인했습니다. 회귀 검사 중 발견한 다수전 처리 순서도 문자 ID 기준으로 명시해 실행별 차이를 제거했습니다.
