# 신체 상태 마무리와 전투 기반

## 원래 6개 항목 기준 진행 상태

| 번호 | 항목 | 구현 상태 |
|---|---|---|
| 1 | 캐릭터 공통 기반 | 공통 본체, 정의/실행 상태, 고유 ID |
| 2 | 이동·제어 분리 | 이동 컴포넌트, 플레이어 입력, AI 명령 |
| 3 | 상호작용 | 대상 감지, 공통 컴포넌트와 개별 행동 |
| 4 | 관계 | 방향 그래프, 대화 조건·완료 보상, 저장 기반 |
| 5 | 신체 상태 | 허기·갈증·피로, 섭취·휴식·수면·게임 시간·HUD + 별도 스태미나 |
| 6 | 전투 기반 | 체력·회복·전투 불능, 선택적 전투 컴포넌트, 기본 공격·피격 |

5번의 기존 기능에 단기 스태미나를 추가하고, 6번의 전투 기반을 구현했습니다. 무기·스킬·콤보·본격적인 적 AI는 전투 방식 결정 후 확장할 범위입니다.

## 현재 플레이 확인

1. 운동장 오른쪽의 훈련 로봇 `(1420, 570)`에 다가가 바라봅니다.
2. **J / 게임패드 B**로 기본 공격합니다. 캐릭터 위의 체력 막대와 공격·피격 표시, HUD의 스태미나를 확인합니다.
3. 로봇은 피격 후 **0.75초** 뒤 공격자를 향해 반격을 시도합니다. 거리 밖으로 피하거나 벽이 가리면 맞지 않습니다.
4. **E**로 훈련 로봇을 회복하고, 아직 예약된 반격도 취소할 수 있습니다.
5. 체력 0이면 이동·상호작용·공격이 차단됩니다. **R**로 체력·스태미나를 회복하고 체크포인트로 복귀합니다. 전투 불능 중에도 Esc로 일시정지할 수 있습니다.
6. 운동장 벤치나 교실 휴식 침상에서 쉬면 장기 피로가 줄고 스태미나가 전량 회복됩니다.

일반 학생인 서윤·민재에는 `CombatComponent`를 붙이지 않았으므로 기본 공격 대상이 아닙니다. R은 살아 있을 때는 기존 체크포인트 이동만 수행하며 체력을 회복하지 않습니다.

## 클래스와 책임

| 클래스 | 책임 |
|---|---|
| `HealthComponent` | 현재/최대 체력, 피해, 회복, 명시적 부활, 피격 보호 토큰과 시그널 |
| `DamageEvent` | 공격 주체의 고정 ID와 요청 피해량 |
| `CombatComponent` | 공격 가능 여부, 진영·거리·방향·벽 검사, 대기시간과 스태미나 지불, 타격 요청 |
| `AttackDefinition` | 피해량·거리·각도·대기시간·스태미나 비용 설정 Resource |
| `StaminaComponent` | 단기 자원 소비와 실제 시간 회복, 변경 시그널 |
| `StaminaProfile` | 최대 스태미나·초당 회복량·회복 시작 지연 Resource |
| `TrainingController` | 훈련용 반격 의도와 지연 처리 |
| `CombatFeedback` | 체력 막대, 공격 호, 피격·전투 불능 표시 |
| `TrainingResetInteraction` | 현재 월드의 훈련 로봇 회복과 반격 취소 |

`SchoolCharacter`의 `Action`은 `MOVE`, `INTERACT`, `ATTACK`, `RECOVER`로 나뉩니다. 기존 전체 제어 잠금은 이 행동들을 모두 차단합니다. `HealthComponent`와 `StaminaComponent`는 공통 캐릭터 씬의 자식이고, 전투 참가는 `CombatComponent`를 붙여 선택합니다. 스태미나는 캐릭터 정의에 프로필을 연결할 때 활성화됩니다.

캐릭터의 현재 체력과 스태미나는 `CharacterState`가 보관합니다. 컴포넌트에 중복 원본을 만들지 않습니다. 최대 체력은 `CharacterDefinition.max_health`, 최대 스태미나와 회복 규칙은 `stamina_profile`에 있습니다.

## 공격 실행 규칙

```text
PlayerController: J / 패드 B
  → InGame: 공격 요청
  → CombatComponent: 행동 잠금·프로필·대기시간·스태미나 확인
  → 같은 월드의 진영·거리·방향·벽 조건에 맞는 대상 선택
  → 스태미나와 대기시간 적용
  → 공격 표시 시그널 후 대상 조건 재검사
  → 대상 HealthComponent에 DamageEvent 전달
  → 실제 피해량과 체력 변경 시그널
```

- 기본 공격은 즉시 판정하는 단일 대상 근접 공격입니다. 조건을 만족하는 가장 가까운 대상을 고릅니다.
- `try_attack(target)`으로 명시한 대상이 유효하지 않으면 소비 없이 거부합니다.
- `try_attack()`에서 대상이 없으면 허공 공격이 되며 정상 비용과 대기시간을 사용합니다.
- `team`, `target_teams` 비트 마스크로 대상 진영을 제한합니다.
- `set_scope(world)`로 지정한 같은 월드의 캐릭터만 공격합니다. 같은 좌표에 다른 월드가 로드되어 있어도 타격하지 않습니다.
- 자신, 제거된/비활성 대상, 전투 컴포넌트가 없는 캐릭터, 체력 0 또는 피격 보호 중인 대상은 제외합니다.
- 공격 시작 알림 이후에도 거리·벽·대상 유효성을 다시 검사합니다. 알림 중 대상이 이동해도 조건을 우회하지 않습니다.
- 공격·피해 알림 도중 같은 처리를 재귀적으로 실행할 수 없습니다.

|---|---:|---:|

| 피해량 | 25 | 10 |
| 사거리 | 85px | 85px |

수치는 `data/combat/player_attack.tres`, `training_attack.tres`에서 편집합니다. 공유 Resource는 설정으로 사용하고 실행 중에는 변경하지 않습니다.

## 피로와 스태미나의 차이

| 구분 | 장기 피로 | 단기 스태미나 |
|---|---|---|
| 소유 | `NeedsState` / `NeedsService` | `CharacterState` / `StaminaComponent` |
| 시간 기준 | 게임 시간 | 캐릭터가 행동 가능한 실제 플레이 시간 |
| 사용 방향 | 쌓일수록 피곤함 | 공격할 때 감소 |
| 회복 | 휴식·수면의 게임 시간에 비례 | 마지막 소비 후 지연을 거쳐 자동 회복 |
| 기본 수치 | 기존 학생 프로필 유지 | 최대 100, 지연 1초, 초당 18 회복 |

공격에 스태미나를 써도 피로를 직접 변경하지 않습니다. 스태미나가 부족하면 공격하지 못하지만 이동은 가능합니다. 수치별 이동 페널티나 자동 기절은 아직 적용하지 않았습니다.

`NeedsComponent.rest()`가 휴식/수면을 성공적으로 완료하면 선택적 형제 `StaminaComponent`의 전량 회복 API를 호출합니다. 순수한 `NeedsService`는 장기 신체 상태와 게임 시간 계산만 담당합니다. 단순한 게임 시간 이동만으로 전투 자원이 회복되지는 않습니다.

대화·일시정지·전투 불능 중에는 스태미나 자동 회복과 공격 대기시간이 진행되지 않습니다. 현재 로드된 캐릭터의 실제 물리 프레임으로 갱신하므로 맵 밖 캐릭터에게 전투 자원 자동 회복을 시뮬레이션하지 않습니다.

## 체력과 전투 불능

- `take_damage(event)`: 실제로 감소한 체력을 반환합니다. 초과 피해는 0에서 제한합니다.
- `heal(amount)`: 실제 회복량을 반환합니다. 최대 체력을 넘지 않으며 체력 0에서 자동 부활하지 않습니다.
- `revive(amount)`: 체력 0인 캐릭터만 명시적으로 부활시킵니다. 다른 시스템의 행동 잠금은 해제하지 않습니다.
- 체력 0 진입 시 활동 상태를 `INCAPACITATED`로 변경하고 현재 이동을 멈춥니다.
- 맵 재생성으로 체력이 초기화되지 않습니다. 다시 생성되는 캐릭터는 ID 기반 저장 상태에 연결됩니다.
- 불러온 체력은 정의의 최대 체력으로 제한하고, 체력 0은 전투 불능 상태로 정규화합니다.

대화 컨트롤러는 플레이어의 피격 보호 토큰도 소유합니다. 대화 완료·취소·컨트롤러 제거 시 자신의 토큰만 해제합니다. 메뉴 일시정지는 컴포넌트 처리를 멈추며 직접 공격·피해·소비 호출도 거부합니다.

Health는 피해가 어디서 왔는지에 따른 거리·진영 규칙을 결정하지 않습니다. 전투 컴포넌트가 전투 판정을 하고, 향후 환경 피해는 Health의 같은 API를 사용할 수 있습니다.

## UI와 새 캐릭터 설정

`HealthComponent.changed` / `StaminaComponent.changed` → `InGame`의 숫자 시그널 → `GameCoordinator` → `GameUI/HUD`로 연결합니다. HUD에는 캐릭터 노드나 컴포넌트 참조를 전달하지 않습니다.

새 전투 캐릭터에는 다음을 설정합니다.

1. 공통 캐릭터 기반, 고유 ID와 정의 Resource.
2. `CombatComponent` 자식, `AttackDefinition`, 진영과 공격 대상 마스크.
3. 스태미나 비용을 사용한다면 정의에 `StaminaProfile` 연결.
4. 시각 피드백이 필요하면 `CombatFeedback` 추가.
5. 컨트롤러가 공격 의도를 `try_attack()`에 전달. 월드에서 생성할 때 상태 바인딩과 전투 scope 설정.

체력 기능만 있고 공격하지 않는 캐릭터도 가능합니다. 플레이어의 Combat 컴포넌트를 제거해도 이동·상호작용·UI 구성은 동작합니다.

## 저장과 검증

캐릭터 저장소는 **버전 3**으로 확장했고 버전 1·2도 읽습니다. 이전 데이터의 누락된 스태미나는 프로필 바인딩 시 최대치로 초기화합니다. 현재 체력·전투 불능·스태미나 값은 저장하지만 공격 대기시간, 반격 예약, 피격 보호·행동 잠금 토큰, 표현 타이머는 저장하지 않습니다.

```sh
godot --headless --path gd-game-02 --editor --import --quit
godot --headless --path gd-game-02 --script res://tests/combat_test.gd
```

새 검사는 피해/회복/부활, 잠금 소유권, 스태미나 소비·회복, 피로와의 독립성, 거리·방향·벽·진영·월드 범위, 실제 J 입력과 반격, 대화·일시정지, R 복귀와 E 훈련 회복, 선택적 Combat 제거, 저장 구버전 마이그레이션을 확인합니다. 기존 캐릭터·생활·관계·게임·대화·UI 검사도 함께 유지합니다.
